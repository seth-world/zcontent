Symbols

 

Symbols are named literals of any data type (Uri, String, Integer, Float, Date, Resource, Checksum).

Symbols may be used in expressions : selection clauses, arithmetic expressions, logical expressions etc.

 

declare <symbol name> = <literal value> ;

 

Creates a symbol with name <symbol name> and set its value content to <literal value>.

<literal value> is

  • •.of any data type ,  

  • •.may be an  arithmetic expression composed of literals and other defined symbols.
    Entity fields are not allowed 

  • •.a logical expression composed of literals and other defined symbols.
    Entity fields are not allowed 

 

set <symbol name> = <literal value> ;

 

Changes actual value of symbol with name <symbol name> with <literal value>.

<literal value> may be of any data type regardless symbol actual content data type.

 

Changes the content value of symbol <symbol name> to <literal value>.

Remark : <literal value> may be of any data type regardless what actual symbol content is.

 

clear <symbol name> ;

 

Removes <symbol name> from the list of symbols and releases symbol associated resources from memory.

After this instruction, symbol <symbol name> is not known anymore.

 

save symbols to <xml file path> ;

 

Saves the whole symbol list containing symbols already declared (and not cleared).

List is saved in xml format within file with path <xml file path>.

If this file already exists, then it is simply replaced without any backup.

 

If no file name extension is mentioned in <xml file path> , then <.xml> extension will be automatically added.  

 

 

save symbols ;

 

If no file path is mentioned, then symbols are saved in default symbol name.

 

 

load symbols from <xml file path> ;

 

load symbols ;

Resource

 

A resource defines a unique identifier for any object across the application framework.

It is allocated by lockmanager.

 

ZResource(ZEntity,id);

 

where :

 

ZEntity represents a resource class that could be :

 a ZEntity symbol

 an hexadecimal number

 a decimal number

 later numbers both corresponding to an object class value.

 

id is a sequential number delivered by LockManager according ZEntity object class value.

This number may be either decimal or hexadecimal.

 

 

Examples :

 

ZResource(ZDocPhysical,2)  : unique resource for class ZdocPhysical with id 2

 

ZResource( ZEntity_URI  , 0x1AF7 )  : unique resource for class ZEntity_URI with id 0x1AF7 (10’503 decimal)

 

ZResource( ZEntity_URI  , 10503 ) : same object as previous

 

 

 

ZEntity symbols are defined on a per application basis in xml file zsearchparserzentity.xml.

(See file zsearchparserzentity.xml)

 

ZEntity symbols corresponding values are either system or user defined :

 

value range ] 0, 0xFFFFF] is reserved for user usage.

Values above 0x100000 are reserved for system usage.

 

 

 

 

Special case : DECODE

DECODE modifier may be applied to any field, literal, expression result.

 

It consists in translating field, literal expression result by a match with an entity.

 

Syntax

 

<field name>.DECODE  ( <entity name>,<key field>,<resulting field>  [ , <match operator> = ZSOP_EQUAL  ] )

 

<key field> is a valid field from <entity name>

<resulting field> is a valid field from <entity name>

 

<match operator> is one of { == ,  > , < . >= , <= }

 

By default (if <match operator> is omitted) operator == (equal) is taken.

 

field name content is compared to <entity name>.<key field> using compare operator.

<resulting field> is returned for the first match of logical expression.

 

Resulting field type

 

resulting field type is the type of <resulting field>

 

 

 

Field selection clause

 

This clause sets the fields to be returned from entity.

It may mix pure fields from base entity, arithmetic expressions or resulting fields from DECODE clause.

Field selection clause is a set of field expressions separated by COMMA sign.

Field expression

 <entity>.<field>.<modifier>

 

  <entity>.<field>

 

  <field>.<modifier>

  <field>

 

  NB: <modifer> itself and its possible arguments will be extracted by callee routine (i. e. _parseOperandField())

 

  <arithmetic expression>

 

        <literal> \          / <literal>

           or      <operator>    or

        <field>   /          \  <field>
