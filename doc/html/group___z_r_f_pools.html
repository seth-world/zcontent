ZRandomFile Blocks Pools
ZRandomFile Random Access File for content storage

ZRandomFile is organized by blocks. ZRandomFile manages 3 blocks pools, among which 2 are fundamental. These pools are maintained and located within ZFileControlBlock in the header file.

ZBlockAccessTable (abbreviated ZBAT)
This primary pool contains all references to active blocks(State = ZBS_Used). The order of blocks within this pool defines the relative position of the access to blocks within ZRandomFile.
See also
Relative rank of a record for a ZRandomFile or ZMasterFile. ZBlockState_type
ZFreeBlockPool (abbreviated ZFBT)
This primary pool contains all references to freed (logically deleted) blocks within the file (State=ZBS_Free). So that, use of ZRandomFile::zremove will not physically suppress the block. The removed block is simply removed from ZBAT and added as a new entry within ZFBT. It is then available for being allocated to a newly created record thru ZRandomFile::_getFreeBlock routine.
ZDeletedBlockTable (abbreviated ZDBT)
This secondary pool is maintained by grabbing process and free block allocation process. when a free block is grabbed to be agglomerated to another free block in the grabbing algorithm, then its track is not lost (excepted when using option HighwaterMarking). This block is a set as a new entry to ZDBT. when the container block will be allocated, then all ZDBT reference to blocks included within the allocated block will be suppressed.
