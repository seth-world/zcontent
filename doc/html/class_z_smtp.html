IMAP uses port 143, but SSL/TLS encrypted IMAP uses port 993. POP uses port 110, but SSL/TLS encrypted POP uses port 995. SMTP uses port 25, but SSL/TLS encrypted SMTP uses port 465. SMTP systems that offer message submission over port 587 require clients to use STARTLS to upgrade the connection and also require a username and password to authenticate

References: https://tools.ietf.org/html/rfc5321 https://www.samlogic.net/articles/smtp-commands-reference.htm

smtp send mail protocol sequence : typical short session

<connection to server::port> S:"220" C:"EHLO localhost\r\n" S:"220" or "250" C:"STARTTLS\r\n" S:"250" ->startEncryption C:EHLO localhost\r
" S:"250" C:"AUTH LOGIN\r

" S:"334" C:<passwordB64encoded>"\r
" S:"235" Appearantly for Google it is mandatory to have MAIL FROM and RCPT email formated the following way -> <email@gmail.com> C:"MAIL FROM:<"<senderemailaddress>">\r
" S:"250" C:"RCPT TO:<"<recipientmailaddress>">\r
" S:"250 OK" [ C:"RCPT TO:<"<recipientmailaddress>">\r
" S:"250 OK" ... ] as many times as CC recipients server returns "550" -> recipient is known not to be a deliverable address C:"DATA\r
" S:"354" C:<messagetext>"\r
.\r
