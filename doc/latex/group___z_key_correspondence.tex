\doxysubsection{Using ZKey \+: Correspondence between data types}
\hypertarget{group___z_key_correspondence}{}\label{group___z_key_correspondence}\index{Using ZKey : Correspondence between data types@{Using ZKey : Correspondence between data types}}
Setting a ZKey object with values implies a control of data types \+: data type of value to set vs data type of key field.

\begin{DoxyParagraph}{Corresponding sizes of Natural vs Universal size}
Additionnally there is a control of size of value vs natural size of key field in case of array or pointer or class.
\end{DoxyParagraph}

\begin{DoxyItemize}
\item Size principles \+: Value size must be less than or equal to key field size. If size of value is less than size of key field then key field is padded to binary zero. If size is greater (for instance sizeof (class)), then a warning message is emitted to stderr and size is adjusted to key field size without being rejected with an error status.
\item special case \+: Strings. Strings are processed apart from other data field. A string MUST have mandatorily a fixed array of char as Key data type. But this key field can be set with many data types (see further).
\end{DoxyItemize}

\begin{DoxyParagraph}{Correspondence Key field data type vs input value data type}

\end{DoxyParagraph}

\begin{DoxyItemize}
\item array of char \+: valid input value types are
\begin{DoxyItemize}
\item array of char \+: size of array is checked and value must be less or equal than key field
\item pointer to char (C string) \+: size is given by \doxylink{zdataconversion_8h_abca6a6e5a79bb4856b5a33f58812c899}{strlen()}. if value size exceeds key field array size then value size is truncated without error status.
\item std\+::string \+: key field is loaded with std\+::string content.\+If value size exceeds key field array size then value size is truncated without error status.
\item pointer to std\+::string \+: key field is loaded with std\+::string content.\+If value size exceeds key field array size then value size is truncated without error status.
\end{DoxyItemize}
\item Atomic data \+: valid input value types are
\begin{DoxyItemize}
\item same atomic data type (there could be a data conversion)
\item pointer to the same atomic data type (there could be a data conversion)
\end{DoxyItemize}
\item Arrays \+: valid input value types are
\begin{DoxyItemize}
\item arrays of same atomic data type (there could be a data conversion). size must less or equal to key field array size. if size of value is less, key field size is padded with binary zeroes \begin{DoxyRefDesc}{Bug}
\item[\mbox{\hyperlink{bug__bug000003}{Bug}}]arrays as input value generates compilation error due to a mismatch of types during compilation.\end{DoxyRefDesc}

\end{DoxyItemize}
\end{DoxyItemize}

\begin{DoxyParagraph}{Atomic input data type conversion}

\end{DoxyParagraph}
There should be a correspondance between atomic data type for the key field and for the value to set the field with. If atomic data types are not the same (value to set and key field type) then a conversion (cast) is done to the destination keyfield type using \doxylink{zdataconversion_8h_abca6a6e5a79bb4856b5a33f58812c899}{\+\_\+convert\+Atomic\+Key\+Field\+Value()} routine.
\begin{DoxyItemize}
\item for atomic data \+: type conversion is done (reverse byte order if endian, sign byte)
\item for arrays \+: any single atomic data value of the array is converted
\item for pointers \+: any single atomic data value the pointer points to is converted
\item for classes \+: there is no conversion at all, and raw data is moved "{}as is"{} to index key. 
\end{DoxyItemize}
