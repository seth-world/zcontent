\hypertarget{_z_r_f_quick_start_ZRFQSIntro}{}\doxysection{\texorpdfstring{Introduction -\/ Example presentation}{Introduction - Example presentation}}\label{_z_r_f_quick_start_ZRFQSIntro}
This chapter is a user\textquotesingle{}s guide concerning the use of \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File}.

We will follow an example all accross this chapter with a simple data definition. Indeed this example is silly, and not realistic. But this is for the purpose of showing usage and possibilities of \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} methods.

In this example, we will
\begin{DoxyItemize}
\item load in a ZRF a mix of structured data and informal, varying length data with various format.
\item feed ZRF with data
\item remove records
\item search for data using field definition capabilities and \doxylink{classzbs_1_1_z_r_f_collection}{ZRFCollection} object
\item use some ZRF utilities

At this stage, \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} structure is created including on storage, with all necessary infra-\/data to work with (mostly set to their default values).

By default, grab\+Free\+Space is set to on (true), and high\+Water\+Marking is set to off (false).

Allocated\+Blocks and Block\+Extent\+Quota,the pool tables size parameters, are set to their defaulted parameters (\+\_\+cst\+\_\+default\+\_\+allocation and \+\_\+cst\+\_\+realloc\+\_\+quota) see\+: ZArray

We could change that (see further).

But one rather important parameter is Block\+Target\+Size. We will set it to a value (this is not mandatory, but wishable).

\begin{DoxyNote}{Note}
We remark that zcreate method has set up internal \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} data structure. Even if the file has been closed, this data remains available and does not need to be mentionned again. Using this facility, the first time we create or open a file, we have to mention required infradata for the given file. Successive sessions (open/close) could be done without mentionning again this infradata.
\end{DoxyNote}

The masterpiece of free sequential selection and access on a \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} is \doxylink{classzbs_1_1_z_r_f_collection}{ZRFCollection} object. We will so define a \doxylink{classzbs_1_1_z_r_f_collection}{ZRFCollection} that will hold and manage our request.

This collection will be recursively used and refined in changing the selection criterias.

This will be done for
\begin{DoxyItemize}
\item a string selection
\item a selection on a float
\end{DoxyItemize}\hypertarget{_z_r_f_quick_start_ZRFQSSearchString}{}\doxysubsection{\texorpdfstring{Selection on adhoc fields considered as Cstring}{Selection on adhoc fields considered as Cstring}}\label{_z_r_f_quick_start_ZRFQSSearchString}
We will take advantage of field String1 from \doxylink{struct_t3}{T3} structure, and search as a string a certain substring contained somewhere in the defined field.

Then we will refine this search using another substring.\hypertarget{_z_r_f_quick_start_ZRFQSStr1}{}\doxysubsubsection{\texorpdfstring{Establish the first collection of records ranks}{Establish the first collection of records ranks}}\label{_z_r_f_quick_start_ZRFQSStr1}
The first search will be a global search, searching at once for all occurrence of record ranks satisfying the selection criteria.

At any moment, it is possible to upgrade a \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} to a \doxylink{classzbs_1_1_z_master_file}{ZMaster\+File}. Why do such a conversion ?
\begin{DoxyItemize}
\item because a \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} is not capable of maintaining Journaling facilities.
\item because you may create indexes.
\end{DoxyItemize}

\begin{DoxyNote}{Note}
creating indexes for a \doxylink{classzbs_1_1_z_master_file}{ZMaster\+File} is not mandatory. It is always possible to continue using it a \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} while taking benefit from Journaling. 
\end{DoxyNote}
