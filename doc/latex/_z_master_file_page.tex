\doxylink{classzbs_1_1_z_master_file}{ZMaster\+File} (further abbreviated ZMF) uses \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} base class in order to provide an indexed acccess to content with variable size on disk. \begin{DoxySeeAlso}{See also}
\doxylink{classzbs_1_1_z_master_file}{ZMaster\+File}
\end{DoxySeeAlso}
It is composed of three main components (and several others) \+:


\begin{DoxyItemize}
\item ZIndex\+File class
\begin{DoxyItemize}
\item Holds and manage one index key for \doxylink{classzbs_1_1_z_master_file}{ZMaster\+File}.
\item Manages all extractions and conversion for building a coherent index key according its key dictionary.
\end{DoxyItemize}
\item \doxylink{classzbs_1_1_z_master_file}{ZMaster\+File} class itself
\begin{DoxyItemize}
\item Holds the effective content
\item Manages ZIndex\+File objects (one object per defined key)
\end{DoxyItemize}
\item ZKey class
\begin{DoxyItemize}
\item Builds key values up to be used by ZMF from litteral or any given data value, or extracts key value from \doxylink{classzbs_1_1_z_master_file}{ZMaster\+File} record
\item Key value is ready to be used in index queries
\end{DoxyItemize}
\end{DoxyItemize}

From a user point of view, ZIndex\+File may stay ignored.

In addition to \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} facilities (random access per logical relative rank), it allows \+:


\begin{DoxyItemize}
\item creating and maintaining indexes on the content, so that access can be made by index key content rather than relative position within file
\item managing Journaling on the operations on file
\item managing History on the operations on file
\end{DoxyItemize}

Updates on \doxylink{classzbs_1_1_z_master_file}{ZMaster\+File} and ZIndex\+File(s) are made using internal 2 phases commit process to increase performance in lowing storage access number with rollback/commit mechanism.\hypertarget{group___z_master_file_group_ZMFGMain}{}\doxysubsection{\texorpdfstring{Main methods}{Main methods}}\label{group___z_master_file_group_ZMFGMain}

\begin{DoxyItemize}
\item zcreate creates the file and its infra-\/data structures \begin{DoxySeeAlso}{See also}
ZMaster\+File\+::zcreate
\end{DoxySeeAlso}

\item zcreate\+Index creates an Index defined by its dictionary
\item zadd adds a record logically positionned at the end of the record list. Physically the block containing the user\textquotesingle{}s record may be anywhere on the file\textquotesingle{}s surface according the better placement capability.
\item zremove logically deletes a record. block containing record is then placed in free block pool. if grab\+Free\+Space option is chosen then adjacent free blocks are agglomerated to make one unique free block and benefit from the whole space set.
\item zget reads a record from file according to its logical relative position and returns records content.
\item zgetnext reads the next record
\item zget\+Field gets a field given by the relative position of its record, its offset and its length.
\end{DoxyItemize}\hypertarget{group___z_master_file_group_ZMFGSpecial}{}\doxysubsection{\texorpdfstring{Special methods}{Special methods}}\label{group___z_master_file_group_ZMFGSpecial}

\item zrecover \+: recovers a free pool block. It creates back a block from first freed block contained in free block and ungrab all deleted block agglomerated to it. these undeleted blocks become free blocks in free pool and can be themselves recovered.

\begin{DoxyParagraph}{What if a key field points out of a varying record boundaries ?}

\end{DoxyParagraph}
As \doxylink{classzbs_1_1_z_master_file}{ZMaster\+File} has a varying record size, from case to case, a field may point to outside the Master\+File record highest boundary. In this case, the field is taken (as if it has been extracted) as a binary zeroed field, whatever its data type could be. In case of signed numeric arithmetic data type, this means \textquotesingle{}negative zero\textquotesingle{} value, which is not a correct key data format (arithmetic zero is considered as positive).

\begin{DoxyParagraph}{Using keys with ZMaster\+Files}

\end{DoxyParagraph}
Any ZIndex\+File relates to a (father) \doxylink{classzbs_1_1_z_master_file}{ZMaster\+File} from which it gets its index data. A key structure must be defined using a Key dictionary and then will be populated transparently as soon as there will be an action done on \doxylink{classzbs_1_1_z_master_file}{ZMaster\+File} its relates to.

Key is used to search \doxylink{classzbs_1_1_z_master_file}{ZMaster\+File} content using a key value, total value or partial value.

The zstatistics struct This object is used to store statistic on performance during searches on Indexes for a \doxylink{classzbs_1_1_z_master_file}{ZMaster\+File}.  

\doxylink{classzbs_1_1_z_master_file}{ZMaster\+File} embeds a set of Performance statistics facilities that gathers and extends the tools from \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File}.

The main objective is to
\begin{DoxyItemize}
\item follow activity on the different components of \doxylink{classzbs_1_1_z_master_file}{ZMaster\+File}
\begin{DoxyItemize}
\item \doxylink{classzbs_1_1_z_master_file}{ZMaster\+File} behavior
\item The behavior of each individual ZIndex\+File (one per defined index key)
\end{DoxyItemize}
\item monitor Performances on each of these above components with dynamic sessions You can then dynamically start a monitoring session and get the results when you wish so. These results will include a dynamic timer result with a delta time showing elapsed time since the session has been started.
\end{DoxyItemize}

\begin{DoxySeeAlso}{See also}
\doxylink{group___z_r_f_s_t_a_t_s}{Dump utilities and Statistical tools for ZRandom\+File}
\end{DoxySeeAlso}
Each high level operation (zsearch, zadd, etc...) gives its own zstatistics values, specific to the operation, whatever the result is, even in case of failure.

As it accesses \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File}, it collects also the whole \doxylink{class_z_r_f_p_m_s}{ZRFPMS} data set for the operation.
