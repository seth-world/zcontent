ZMaster\+File\+::zapply\+XMLFile\+Definition

Using this static routine, you may perfectly change multiple parameters for a file at a time, including modifying or even adding indexes, using xml file description, under certain conditions.

This modified description should point to an existing file that have to be closed prior invoking this above mentionned routine \+: file will be opened with exclusive access.\hypertarget{group___x_m_l_group_XMLZRF}{}\doxysubsubsection{\texorpdfstring{ZRandom\+File (and therefore ZMaster\+File base) changes}{ZRandomFile (and therefore ZMasterFile base) changes}}\label{group___x_m_l_group_XMLZRF}
Constraints \+:


\begin{DoxyItemize}
\item changing URIContent implies that the changed URIContent points to an existing ZRandom\+File/\+ZMaster\+File corresponding to description. This means that if you change this value, a valid path file pointing to the file you want to change must be indicated.
\end{DoxyItemize}

Some fields are not modifiables \+:


\begin{DoxyItemize}
\item URIHeader \+: as it is deduced from content main file name URIContent at open time and create time, it CANNOT be modified\+: any modification will not been taken into account
\item URIDirectory\+Path \+: as it is deduced from content main file name URIContent at open time and create time, it CANNOT be modified\+: any modification will not been taken into account
\end{DoxyItemize}

Modification on base Random\+File parameter field will cause a change in the header file.


\begin{DoxyItemize}
\item Block\+Extent\+Quota \+: will change the behavior of the pool tables \+: how much elements these tables will be increased at each time they need more space. see \doxylink{zdataconversion_8h_abca6a6e5a79bb4856b5a33f58812c899}{zload\+XMLFile\+Definition}
\item Initial\+Size \+: this change the initial size of the file. This value will stay in header and is used when the file is cleared as the free block size the empty file will be loaded with.
\item Block\+Target\+Size \+: you may adjust this value for performance purpose according the various stat you may report. see \doxylink{group___z_r_f_s_t_a_t_s}{Dump utilities and Statistical tools for ZRandom\+File}
\end{DoxyItemize}\hypertarget{group___x_m_l_group_ZMFCHG}{}\doxysubsubsection{\texorpdfstring{ZMaster\+File changes}{ZMasterFile changes}}\label{group___x_m_l_group_ZMFCHG}

\begin{DoxyItemize}
\item Duplicates \+: There is no specific problem to change a value from ZST\+\_\+\+NODUPLICATES to ZST\+\_\+\+Duplicates. However, changing ZST\+\_\+\+Duplicates to ZST\+\_\+\+NODUPLICATES may cause Index to be rejected if a duplicate key is encountered during index rebuild. In this case, Index will be rejected and former Index will be lost.
\end{DoxyItemize}

\begin{DoxyNote}{Note}
If a typo is detected then it will be considered as ZST\+\_\+\+Duplicates.
\end{DoxyNote}
Any index without modification, or with modifications that only concern "{}non modifiable"{} fields, then index is not modified and not rebuilt.

Any modification(s) on an index will cause \+:
\begin{DoxyItemize}
\item If index does not exist \+:
\begin{DoxyItemize}
\item Its creation
\item Its rebuild
\end{DoxyItemize}
\item If index already exist \+:
\begin{DoxyItemize}
\item Its rebuild \+: rebuild process clears the index file first, then re-\/create all indexes from master file.
\end{DoxyItemize}
\end{DoxyItemize}

Index modification(s) that are not involving such process is
\begin{DoxyItemize}
\item Key dictionnary field name change \+: field name is only changed within appropriate dictionary with no index rebuilt. see further Problems
\end{DoxyItemize}

\begin{DoxyWarning}{Warning}
Changing fields description position in the xml file will change their rank in dictionary REGARDLESS the $<$\+Rank$>$ tag that will not been taken into account.
\end{DoxyWarning}
These modifications could be applied either on Index major fields or one field of its key dictionary.

\begin{DoxyParagraph}{Potential Problems}

\end{DoxyParagraph}

\begin{DoxyItemize}
\item Two indexes have the same name \+: this is not allowed and creation will be rejected. So, if you duplicate an index definition, you must at least change its name.
\item Changing the name of an index \+: as a new the file corresponding to former index name must be manually removed
\item Inserting an index \+: all indexes after the insertion point will be considered as new indexes. 
\end{DoxyItemize}
