\hypertarget{_z_random_file_page_ZRFMainZRandomFileGroup}{}\doxysection{\texorpdfstring{ZRandom\+File \+: Random Access File for content storage}{ZRandomFile : Random Access File for content storage}}\label{_z_random_file_page_ZRFMainZRandomFileGroup}
\doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} (also further abbreviated ZRF) is the base tool for managing content with variable size on disk.

It allows a random access per logical relative rank to a user record content. Logical relative rank is the user logical rank view and does NOT correspond to physical storage order \+: \begin{DoxySeeAlso}{See also}
\doxylink{group__recordranks}{Relative rank of a record for a ZRandom\+File or ZMaster\+File.}
\end{DoxySeeAlso}
\doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} places the contents according its size to optimize its behavior, AND NOT necessarily according the record creation order.

It manages free space using specific algorithms that reallocate space whenever required and extend the file size only when required.

It shall reserve (allocate) a given disk space at creation time to avoid physical holes on disk.

\doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} offers many optional features, left to the choice, in order to better manage ZRF behavior, knowing there is a choice to make between instant write/delete access time and global performance.\hypertarget{group___z_random_file_group_ZRFGGfs}{}\doxysubsection{\texorpdfstring{grab\+Free\+Space}{grabFreeSpace}}\label{group___z_random_file_group_ZRFGGfs}
Grab\+Free\+Space is an on-\/flow process that consist in agglomerating free blocks before and free blocks after the current block being free. So that the deleted block grabs the available space around him. It reduces the eventuality \+:
\begin{DoxyItemize}
\item to have holes between blocks
\item to have a huge number of atomized free blocks
\end{DoxyItemize}

As grab\+Free\+Space will weight a little bit on resource consumption, it should be carefully used.

grab\+Free\+Space will offer its best when \+:
\begin{DoxyItemize}
\item using varying size record content
\item standard deviation of record size is important compared to block target size (average size of blocks existing in file-\/ or forced value)\+: \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} offers statistical tools to study the records/blocks population and to take appropriate decisions. \begin{DoxyNote}{Note}
block target size is a statistical value that is computed to be the average size of existing blocks withing the file.
\end{DoxyNote}
This means that \+: in case of fixed length record, grad\+Free\+Space option is not appropriate (even if it may be used without any problem), because it may induce a (small) waste of computing time.  
\end{DoxyItemize}\hypertarget{group___z_random_file_group_ZRFGHwm}{}\doxysubsection{\texorpdfstring{high\+Water\+Marking}{highWaterMarking}}\label{group___z_random_file_group_ZRFGHwm}
Using high\+Water\+Marking option parameter, it will zero any removed record content. This option could be of interest to preserve some confidentiality for data.

\begin{DoxyNote}{Note}
When using this option, surface scan will no more show up deleted block headers.
\end{DoxyNote}

For performance purposes, \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} is composed of 2 physical files that may strictly stay aligned \+:
\begin{DoxyItemize}
\item Content file This is the main file that will contain user data. This is the file that is named by used to handle a \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File}. The name of this file is left to user\textquotesingle{}s choice, despite some restrictions(see below). This name will actually be the name of the \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} itself.
\item Header file This file contains infradata that is mandatory to the \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} behavior. The name of this file is deduced from the content file and is stored in the same path that content file.
\end{DoxyItemize}

\begin{DoxyNote}{Note}
\doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} users do not have to care about this duality, excepted when ZRandom\+Files are backuped or moved. Header file name is transparently deduced from the content file name (uri\+String). In a normal usage case, user does not see header file. He only addresses the main \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} content file, the one he named.
\end{DoxyNote}
\begin{DoxyWarning}{Warning}
This implies that header file is absolutely necessary for a \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} to be recognized and to be read. Users should never ever modify directly, or even delete, such files, nor move them without moving the main ZRF content file. In such cases, damages could stay non recoverable. However, there is an utility routine to rebuild a header file in case of damaged header file \doxysectlink{group___z_r_f_utilities_ZRFUtilHRebuild}{ZRF header rebuild}{2}
\end{DoxyWarning}

\hypertarget{_z_random_file_page_ZRFMainPools}{}\doxysubsection{\texorpdfstring{ZRandom\+File Blocks Pools}{ZRandomFile Blocks Pools}}\label{_z_random_file_page_ZRFMainPools}
\doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} is organized by blocks. \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} manages 3 blocks pools, among which 2 are fundamental. These pools are maintained and located within \doxylink{class_z_file_control_block}{ZFile\+Control\+Block} in the header file.

\begin{DoxyParagraph}{ZBlock\+Access\+Table (abbreviated ZBAT)}
This primary pool contains all references to active blocks(State = ZBS\+\_\+\+Used). The order of blocks within this pool defines the relative position of the access to blocks within \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File}. 
\end{DoxyParagraph}
\begin{DoxySeeAlso}{See also}
\doxylink{group__recordranks}{Relative rank of a record for a ZRandom\+File or ZMaster\+File.} \doxylink{group___z_random_file_group_gaeff3dcb5d58e5eb83b4a5ad6410dbd79}{ZBlock\+State\+\_\+type}
\end{DoxySeeAlso}
\begin{DoxyParagraph}{ZFree\+Block\+Pool (abbreviated ZFBT)}
This primary pool contains all references to freed (logically deleted) blocks within the file (State=ZBS\+\_\+\+Free). So that, use of \doxylink{group___z_random_file_group_ga45a6d65b8860755dc62ae3c75e50f568}{ZRandom\+File\+::zremove} will not physically suppress the block. The removed block is simply removed from ZBAT and added as a new entry within ZFBT. It is then available for being allocated to a newly created record thru ZRandom\+File\+::\+\_\+get\+Free\+Block routine.
\end{DoxyParagraph}
\begin{DoxyParagraph}{ZDeleted\+Block\+Table (abbreviated ZDBT)}
This secondary pool is maintained by grabbing process and free block allocation process. when a free block is grabbed to be agglomerated to another free block in the grabbing algorithm, then its track is not lost (excepted when using option Highwater\+Marking). This block is a set as a new entry to ZDBT. when the container block will be allocated, then all ZDBT reference to blocks included within the allocated block will be suppressed.  
\end{DoxyParagraph}

\doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} manage a compound content and does not offers to access content through a dictionary. However, it is possible to access its user content (records) by adhoc fields definition.

A \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} field is a segment of record defined by
\begin{DoxyItemize}
\item its offset from the beginning of the user record,
\item a length.
\end{DoxyItemize}

As it is possible to search for values for a field, it is possible to access directly the field content\+:
\begin{DoxyItemize}
\item to read its content
\item to write its content
\end{DoxyItemize}

In both cases, only the file segment corresponding to the given field will be accessed, so that you may, for example, change only the segment of record corresponding to the defined field.

This is possible using the below two \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} methods

\doxylink{group___z_random_file_group_gad722a3ceb0962ee07c8433029ea5e115}{ZRandom\+File\+::zget\+Single\+Field()} \doxylink{group___z_random_file_group_ga243179a8bebc471d4dc8667b996917cd}{ZRandom\+File\+::zwrite\+Single\+Field()}

\begin{DoxyNote}{Note}
Record data integrity AND data format is left to user\textquotesingle{}s responsibility.  
\end{DoxyNote}
\hypertarget{_z_random_file_page_ZRFMainFreeSearch}{}\doxysection{\texorpdfstring{Searching in free sequential mode}{Searching in free sequential mode}}\label{_z_random_file_page_ZRFMainFreeSearch}
\doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} and \doxylink{classzbs_1_1_z_master_file}{ZMaster\+File} offer the possibility of a free sequential search for all or part of the file\textquotesingle{}s records content. The resulting structure is a collection of \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} records ranks (see \doxylink{zdataconversion_8h_abca6a6e5a79bb4856b5a33f58812c899}{ZRFRanks}) that will match given sequence(s) of bytes (text or binary data) according given rules. Free search is done using user defined fields per rule. A field is defined by
\begin{DoxyItemize}
\item a field offset from the beginning of user\textquotesingle{}s record (starting from zero)
\item a field length \begin{DoxyNote}{Note}
length could be ommitted in giving a negative or null value (reference to a zero long). In this case, the field length will be adjusted to given sequence ZData\+Buffer\+::\+Size attribute.
\end{DoxyNote}
The masterpiece of this free search facility is ZCollection\+\_\+\+Rank that will store matching rules see Z\+::add()
\end{DoxyItemize}

Resulting to this search, a collection of records\textquotesingle{} ranks is given, and may be refined using successive searches that will apply to a previous collection optionally given in input.

As the optional collection to base the search on is safely copied during search initialisation, it is then possible to recursively search on the same collection of records and refine search criterias.

This could be used by example for \+:
\begin{DoxyItemize}
\item searching a first selection giving a first collection of row within ZRFResult\+::\+ZTab\+Idx array
\item then restrict the collection with a new search in passing reference of this array as \doxylink{classzbs_1_1_z_array}{ZArray$<$long$>$} as p\+Collection.
\end{DoxyItemize}

Search will return a \doxylink{classzbs_1_1_z_r_f_collection}{ZRFCollection} object with a collection of record ranks. see \doxylink{classzbs_1_1_z_r_f_collection}{ZRFCollection}.\hypertarget{group___z_r_f_free_search_ZRFFreeModes}{}\doxysubsection{\texorpdfstring{Searching modes}{Searching modes}}\label{group___z_r_f_free_search_ZRFFreeModes}
\begin{DoxyParagraph}{Searching all at once in the whole file or a whole record collection}

\end{DoxyParagraph}
\doxylink{group___z_r_f_free_search_ga0d1109b5a8066fdaa08dbbbe888f3495}{ZRandom\+File\+::zsearch\+Field\+All\+Collection()}

This routine searches all record set for matching fields values and returns the whole collection of records.

\begin{DoxyParagraph}{Searching dynamically by successive calls}

\end{DoxyParagraph}
\doxylink{group___z_r_f_free_search_ga4afe5f1051b94274fc2dc134740da409}{ZRandom\+File\+::zsearch\+Field\+First\+Collection()} \doxylink{group___z_r_f_free_search_ga9a4486437a4982aa14f8861bff66a021}{ZRandom\+File\+::zsearch\+Field\+Next\+Collection()}

These two routines gets dynamically the corresponding records rank, enriching the records\textquotesingle{} collection ranks with matching records during successive calls.

The first one initialize the search and gets the first matching record.

The second one successively gets the next record matching the given sequence.\hypertarget{group___z_r_f_free_search_ZRFFreeSearchType}{}\doxysubsection{\texorpdfstring{Search rules processing options}{Search rules processing options}}\label{group___z_r_f_free_search_ZRFFreeSearchType}
By default, the search is made assuming binary search. However it is possible to specify using optional mask that search should consider field and search sequence as CString (meaning ended with \textquotesingle{}\textbackslash{}0\textquotesingle{}). In this case, this allows to \textquotesingle{}trim\textquotesingle{} leading and trailing spaces.

You may use the following options, depending on ZRFSearch\+\_\+type enum, when searching in free sequential mode in a \doxylink{classzbs_1_1_z_random_file}{ZRandom\+File} \+:

Enum code is given by \doxylink{group___z_r_f_free_search_gaf64b6cef70fbbf38fa4caa789b790656}{ZRFSearch\+\_\+type}

\begin{DoxyParagraph}{Main mask values}

\end{DoxyParagraph}

\begin{DoxyItemize}
\item ZRFEquals\+To equal \+: exact search (the whole fields is the whole sequence)
\item ZRFStarts\+With starts with \+: Field starts with Sequence
\item ZRFEnds\+With ends with \+: Field ends with Sequence
\item ZRFContains contains \+: Sequence is contained somewhere within Field
\end{DoxyItemize}

\begin{DoxyParagraph}{optional ORed mask}

\end{DoxyParagraph}
The following masks have to be ORED with one of the previous value to refine the search comparizon behavior.
\begin{DoxyItemize}
\item ZRFString the search sequence AND the read fields are to be processed as CString (string size is given by \textquotesingle{}\textbackslash{}0\textquotesingle{} character)
\item ZRFTrim\+Space indicates that leading and trailing space characters have to be suppressed before comparing values
\item ZRFCase\+Regardles indicates that comparizon must not take care of upper or lower case
\end{DoxyItemize}\hypertarget{group___z_r_f_free_search_ZRFFreeError}{}\doxysubsection{\texorpdfstring{Size error cases}{Size error cases}}\label{group___z_r_f_free_search_ZRFFreeError}
When searching with ZEquals\+To option set (default option), the size of Sequence ZData\+Buffer must be equal to the field Length, otherwise an error status will be returned before any search operation and a ZException will be set with appropriate message.

Sequence size must be in any case less than or equal to field length.

Hereafter are the cases of incoherence between both ZData\+Buffer\+::\+Size Sequence data and field length \+:


\begin{DoxyItemize}
\item ZEquals\+To size of Sequence ZDatabuffer does not equal search field length.
\item ZStarts\+With Field length is smaller that ZData\+Buffer\+::\+Size.
\item ZEnds\+With Field length is smaller that ZData\+Buffer\+::\+Size.
\item ZContains Field length is smaller that ZData\+Buffer\+::\+Size.
\end{DoxyItemize}

\begin{DoxyNote}{Note}
if Field Length equals ZData\+Buffer\+::\+Size this is equivalent to a ZEquals\+To option.   
\end{DoxyNote}
